# 系统架构与业务规则实现

本系统把财报正文、表格单元、问答转写和待发解释关联到同一套**主张（Claim）**台账，
让财务人员能逐数字回查“它究竟在说什么、依据哪个单元、当前复核状态如何”。
纯标准库实现，金额一律用 `fractions.Fraction` 精确比较；所有“对外动作”只登记本地记录。

## 1. 分层与模块

| 模块 | 职责 |
| --- | --- |
| `irledger/textnum.py` | 中文数字、成数、百分数解析；货币单位到元的精确换算 |
| `irledger/taxonomy.py` | 指标分类（确认收入/订单/预收款/存量）与比较维度（同比/环比/固定汇率/报告汇率） |
| `irledger/table_parser.py` | 表格原文解析，保留行列标题、脚注；单元只继承本表标题单位 |
| `irledger/narrative.py` | 正文/问答/媒体切句、陈述性质标注、省略承接与问答换指标识别 |
| `irledger/corrections.py` | 更正/澄清解析、单元版本管理、按依赖图传播失效 |
| `irledger/engine.py` | 主张工厂、表格派生比率、单位继承检查、数字撞形索引、冲突并列 |
| `irledger/review.py` | 复核状态机、媒体转载独立性、发送前置检查、更正通知 |
| `irledger/pipeline.py` | 端到端编排：装载、增量摄入、更正顺序应用、既有材料挂接 |
| `irledger/store.py` | 本地 JSON 台账持久化 |
| `irledger/cli.py` | 命令行入口 |

## 2. 核心对象

- **Cell（表格单元）**：保留原文数值、生效单位、是否继承单位、来源编号、期间与版本号。
  更正不覆盖旧单元，而是追加新版本（`version` 递增），旧主张仍可回查当时输入。
- **Claim（原子主张）**：一条主张只对应一个指标与一个比较口径。一个答复含两个指标时拆成两条，
  分别复核，互不连坐。字段含陈述性质、证据、分子/分母单元坐标、声称比率与复算比率、依赖单元列表。
- **Evidence（证据）**：区分直接引用、问答转写、派生比率、口径指引；`independent` 标记是否独立来源。
- **Finding（发现）**：冲突 / 口径风险 / 说明，全部带来源编号；系统只并列，不替人选“合理的一边”。
- **OutputRecord（对外材料）**：草稿或已发；发送时保存当时内容快照，追问可查看当时版本。

## 3. 业务规则与落地点

### 3.1 省略承接与问答换指标
`narrative.DiscourseTracker` 按资料顺序记住最近一次带比率陈述的指标/口径（如 FD-B1 的
“订单/固定汇率两成”）。后文出现“海外收入**也**增长两成吗”这类含承接词的比率句时，
记录承接来源；若当前句主语指标与承接指标不同，标 `省略承接-换指标` 并产生
`ellipsis-resolution` 风险发现。答复中“这里两成说前面订单表，不是收入”作为显式澄清登记。

### 3.2 指标与比较口径
- 指标按关键字分类，识别不了归 `未识别` 交人工，不做就近猜测。
- 比较维度：本财年/上财年首季 → 同比；本季/上一季 → 环比；行名含固定/报告汇率 → 对应汇率口径。
- 答复片段本身缺指标词时，受控继承紧邻提问的指标并打 `指标承接提问`，答复结束即清除，不跨问答对串味。

### 3.3 陈述性质不混写
`StatementKind` 区分已实现事实、预测、提问者预设、媒体转述、派生比率：
- 含“若/希望/目标/不能当已实现”的句子标预测，复核直接 `不予确认`，并禁止当事实发送；
- 提问句标提问者预设，未经答复确认不是正式陈述；
- 媒体句标转述，证据 `independent=False`。

### 3.4 单位继承与跨表隔离
- 表内省略单位的单元只继承**本表标题**单位（`unit_inherited` 标记）；
- 无标题单位且单元未标单位 → `unit-missing` 冲突，禁止借其他表单位；
- 单位澄清（FD-C2）只对该表、且数字在指明清单内的单元生效，越表使用被否定单位会判失效；
- `build_digit_collision_index` 列出字面相同但单位/量级不同的数字（如两个 100、800 万元）。

### 3.5 数字与文字冲突
`check_text_number_conflicts` 以主张依赖的**具体单元版本**核对金额，不一致时产生
`text-number-conflict`，并列两边来源，不改写任何一边。派生比率用实际输入数复算，
声称比率与复算比率不一致时产生 `ratio-mismatch`。

### 3.6 更正影响按依赖图传播（关键）
更正/澄清解析为 `CorrectionSpec`，只改其指明的列/单元，范围外保持原值：
1. 目标单元产生新版本；原值与更正文不符时拒绝自动套用并报错；
2. `claims_dependent_on` 按 `depends_on_cells` 依赖图找受影响主张——
   **不搜索被改的数字字符串**，所以分母更正会连带使比率主张失效；
3. 失效主张置 `依据失效`，并用新单元增量重算同表同行的比率（新主张，旧主张保留可回查）；
4. 同一答复/材料中未被更正的另一项指标维持原确认状态，仍可使用。

### 3.7 媒体转载不算独立依据
`_register_media_chains` 识别“媒体乙原文转载甲稿”，建转载链；
`check_media_reprints` 对只有转载来源的主张报 `media-reprint`，独立来源数按链去重。

### 3.8 复核与分发
- `ReviewLedger` 是有限状态机，非法跃迁抛 `ReviewError`，每次跃迁追加 `ReviewEvent`；
- `DistributionLedger.can_send` 要求关联主张全部 `已确认`，预测冒充事实直接拦截；
- `send` 只改本地状态并保存快照，不做真实外发；
- 已发材料在新来源到达后**保留**，通过 `attach_correction` 只挂具体主张+收件人的更正条目，
  不整批撤回无关内容；未发草稿关联失效确认后无法发送。

## 4. 增量摄入

`Pipeline.ingest_records` 按稳定编号去重，可反复导入新季度资料：
- 新表/新正文追加新主张，已登记的事实坐标与比率对通过集合去重；
- 新更正按出现时点生效，失效与重算记录进 `IngestReport`；
- 摄入发现按 `(code, 来源, 信息)` 去重，避免重复堆叠。

## 5. 命令行

```sh
python3 -m irledger.cli check data/case.json        # 冲突、口径风险、数字撞形
python3 -m irledger.cli report data/case.json       # 主张复核状态与材料挂接
python3 -m irledger.cli explain data/case.json CL-020  # 回查输入单元、口径、复算过程
python3 -m irledger.cli send data/case.json OUT2 --store build/ledger  # 发送前置校验+本地登记
python3 -m irledger.cli corrections data/case.json   # 列已发材料需更正的具体主张
```

## 6. 安全与边界

- 读取不可信资料时建议 `python3 -I`，并把数据目录与代码目录分离；
  已验证数据目录内放置的 `json.py` 不会被导入执行。
- 资料中的姓名、金额、规则均为合成演练内容；系统不联网、不发送，只写本地台账。
